# SysMetrics

[English](README.md) · [Русский](README.ru.md)

Диагностика системы для ОС Аврора. Монитор процессов класса htop плюс обзор
системы, сети, устройства и батареи — и диагностика только для чтения, которая
распознаёт документированные неисправности устройства и объясняет их устранение.

> **Порт на ОС Аврора.** Это порт оригинального проекта
> [SysMetrics / harbour-sysmetrics](https://github.com/JimKnopfIoT/harbour-sysmetrics)
> — оригинального проекта, из которого сделан этот порт и его перевод.
> Порт на ОС Аврора выполнил Юрасов Леонид.

## Возможности

- Список процессов: CPU%, RSS, состояние, потоки, nice, пользователь; сортировка
  по любому ключу; текстовый поиск; фильтры «приложения / системные / потоки
  ядра».
- Детали процесса: история CPU, PSS/USS/swap, скорость ввода-вывода, частота
  переключений контекста и страничных отказов, открытые файлы с режимом,
  задействованные узлы /dev с полной идентификацией из sysfs (поставщик,
  продукт, серийный номер, драйвер), сетевые сокеты с индикацией активности,
  потоки, cgroup, оценка доли энергопотребления, оценка нагрузки/разряда по
  правилам.
- Действия: SIGTERM, SIGKILL, SIGSTOP/SIGCONT, renice (только понижение).
- Обзор системы: нагрузка и частота по ядрам, память, скорость сети и диска,
  температурные зоны, батарея (ток, напряжение, мощность, состояние),
  Bluetooth-соединения (BlueZ).
- Режим записи: накапливает процессорное время по процессам за сеанс и
  ранжирует потребителей.
- Проверка перерисовки домашнего экрана: продолжает ли lipstick рисовать на
  простаивающем экране и почему. Измеряется по собственным потокам (пробуждения
  потока отрисовки, главный поток против потока отрисовки), по кадрам дисплея,
  где прерывание при простое виделось нулевым, по доле композитора и по любому
  приложению, подающему кадры в такт. Фоновое наблюдение помечает lipstick в
  списке процессов, когда он перерисовывает без касаний дольше заданного порога,
  и перечисляет то, что было непосредственно перед началом (уведомления с их
  отправителем и числом кнопок, но никогда с их текстом; снимки экрана).
  Управляемый контртест отправляет одно уведомление без кнопок действий и одно с
  ними и измеряет после каждого. Известные дефекты сопоставляются с файлом,
  строкой и точной правкой; приложение никогда ничего не перезапускает и не
  меняет.
- Диагностика на каждой странице подсистемы (сначала факты, находки в конце):
  аппаратные уязвимости CPU (только те, что могут затронуть эту архитектуру;
  зелёный = защита ядра активна), состояние cpufreq-governor и оценка настройки,
  per-touch boost CPU, нижний порог простоя GPU, энергетический запас
  frequency-residency, завышенный D-state-ом load average, здоровье
  core-hotplug на MediaTek, артефакты дублирующегося BT-адаптера/rfkill,
  регуляторный домен WLAN и счётчики падений прошивки, крах camera-provider на
  Xperia 10 III (отсутствующая библиотека HAL, определяется вместе с
  установленным исправлением) и слишком тихая запись camcorder. Вердикт впереди,
  измеренные детали — за касанием, известные исправления названы простым
  текстом; только информирует, никогда не меняет систему. Карточки обзора несут
  точку, когда в их подсистеме есть находка.
- Идентичность чипсета: комбинированный чип WLAN/BT из драйвера, дерева
  устройств и прошивки (шаблоны Qualcomm и MediaTek), USB-контроллер (UDC,
  совместимость из DT, скорости, роли Type-C), номер части SoC из
  /sys/devices/soc0, зарегистрированные службы Android HAL через binder.
- База Android в разделе «Система и CPU»: версия Android, уровень патчей
  безопасности, сборка вендора и отпечаток слоя HAL.
- Трафик Binder (IPC, на котором работает Android-часть системы), считанный из
  собственных счётчиков ядра: вызовы и ответы по процессам и доменам, домены с
  файлом конфигурации, объявляющим каждый из них, неудачные вызовы с
  расшифрованным ответом драйвера (BR_DEAD_REPLY и errno за ним), пулы потоков,
  которым нечем отвечать, односторонние буферы, исчерпывающие себя, и вызовы,
  не вернувшиеся между двумя чтениями. Какой процесс обслуживает
  зарегистрированную службу, устанавливается проверкой живости, на которую
  обязана ответить каждая служба binder, считанной обратно из журнала транзакций
  ядра, — никогда не угадывается по имени; крутящийся поток `binder:<pid>_<n>`
  разрешается в процесс, владеющий пулом. Осиротевшие узлы называют процессы,
  всё ещё держащие на них ссылку, а последние 32 строки журнала драйвера стоят
  там дословно. Каждая цифра — ядровая, каждый порог, превращающий её в вердикт,
  назван рядом.
- Разъём аксессуаров (TOH) на Jolla Phone (2026): состояние линии прерывания,
  напряжение на контакте идентификации и на выходе 5 В, считанные вживую с
  контроллера pogo-pin и нарисованные на разъёме — серый показывает, для чего
  контакт, оранжевый — что устройство сообщает прямо сейчас. Микросхема памяти в
  подключённой крышке читается по I²C и разбирается: поставщик и продукт, полезная
  нагрузка CBOR с именем крышки, пересчитанная контрольная сумма, измеренные на
  шине размер и разрядность адреса микросхемы, сырой блок байт за байтом. Блок
  сверяется по отпечатку с официальными крышками, содержимое которых
  пересобирается из публикуемых производителем источников. Везде только чтение —
  выход 5 В никогда не переключается.
- Страница «Отчёты об ошибках»: готовое к копированию описание устройства (с
  заготовкой для части отчитывающегося) и генератор сведений из логов — назовите
  компонент и получите его точные версии пакетов, запущенные процессы и, в
  root-режиме, подходящие строки journal/журнала ядра единым копируемым блоком.
- Глоссарий, объясняющий каждую цифру, включая техническую подоплёку классов
  уязвимостей и исправления краха камеры.
- Необязательный root-помощник (по умолчанию выключен) открывает детали debugfs:
  идентичность прошивки WLAN, журнал зарядки ядра и выдержки из journal. Чтение
  ограничено фиксированным списком; единственные операции записи — сигналы и
  renice для одного процесса, что и так предлагает страница деталей процесса.

Всё читается из /proc, /sys, D-Bus и rpm на устройстве. Базовое приложение
никогда не обращается к сети.

## Сборка

Собирается Аврора SDK (`sfdk`).

    32-бит (armv7hl):   sfdk build
    64-бит (aarch64):   sfdk -c target=AuroraOS-5.2.0.180-aarch64.default build

Имя пакета: `ru.yurasov.sysmetrics`. Готовые RPM попадают в `RPMS/`.

Внутри git-дерева `sfdk` выводит версию пакета из репозитория и добавляет
суффикс `+<ветка>.<время>.<хеш>`, поэтому две сборки в разное время получают
разные версии. Чтобы получить чистую одинаковую версию для обеих архитектур
(`0.3.11-1`, берётся из spec-файла), собирайте из копии проекта *вне*
git-дерева, но внутри рабочей области SDK.

### Вариант Ultimate (самостоятельная сборка)

    sfdk build -- --with ultimate

Добавляет онлайн-поиск CVE в блоки диагностики — единственная функция, которая
обращается к сети, поэтому он не входит в сборки по умолчанию. Поиск
обращается к ENISA EUVD и отмечает совпадения с каталогом
известно-эксплуатируемых уязвимостей CISA. Пресеты поиска учитывают контекст
(страница сети подставляет радиочип и его стек, страница CPU — ядро/SoC/Android,
…), каждая страница начинается с пустого запроса, а каждый результат несёт
локальный вердикт об исправлении: ✔ не затронуто или исправлено (в rpm-журнале
названа CVE, либо установленная версия выше затронутого диапазона из CVE),
✘ вероятно затронуто (версия внутри диапазона, либо пакет старше CVE), ▢
неизвестно.

## Локализация

Интерфейс доступен на английском (исходный), русском и немецком; переключается
в **Настройки → Язык** (Системный по умолчанию / Русский / Deutsch / English).
Переводы лежат в `translations/` (`ru.yurasov.sysmetrics-ru.ts`,
`ru.yurasov.sysmetrics-de.ts`). Русский перевод машинный — правки вносятся прямо
в `.ts`-файл и подхватываются при следующей сборке.
